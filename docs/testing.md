# Testing

Use real temporary directories, installed artifacts and the actual helper commands. Test the behavior visible to the worker or project owner. Avoid assertions that mirror implementation details.

Run only the relevant file locally: `npm run test -- tests/test_setup.ts`. Never run the full suite locally or repeat a test another agent has already reported green without a new change or unresolved concern. CI runs the nine TypeScript suites and the library check.

The setup suite exercises both prepared local Git checkouts and archives: installation with the seeded loops and roles, configuration, the settings and CLAUDE.md blocks, repair, updates and integrity checks from isolated directories. Local installation tests forbid download, npm and tar commands, and verify that missing dependencies or build output cause errors without writing the target. The framework suite checks the library's loops and roles, the loop and role checks (child loops and drafts included), the hook actions and the worker's ledger and waiting. The contribution suite runs the real installer and git against local bare repositories standing in for GitHub, with a stand-in `gh`: what a contribution carries, and what stops it. The loop view suite installs a worker and a validator project with the real installer and checks what the owner's page shows (steps and their roles, parameter values, runs from the trajectory index, no transcript read), the page written as one file (its data cannot close its script, nothing loaded from elsewhere) and the served page (only its own address, read-only). The Studio suite checks the console's server: the one-time sign-in, what a stranger is refused, the flows it draws from the library's loops (steps, stages, groups, arrows back, ahead and out, parameters joined to their steps) and the quick search; the Studio authoring suite drives the chat against a stand-in `claude`: the request reaching `loop-authoring` with what the owner pointed at, the review note and the draft drawn when the loop waits, the reply passed on unchanged, and the end. Run `npm run build` first because all six consume compiled helpers.

Review sessions are tested against a stand-in `claude` command. Do not add Claude Code authentication checks to tests. Report the difference between archive and helper verification and a real two-machine deployment with Claude Code. Never restart a running Claude Code background service or Paseo daemon to recover from a test timeout.
