# Project environment skill

Each machine has one project skill, `<project>-environment`, in the role's skills directory. The role's setup (`worker-setup` or `validator-setup`) writes it on the real machine, in the directory apply reports as `environment_skill_dir`; agents extend it later. Find out what you can by inspecting the machine; ask the owner only for what you cannot. The skill holds two things and nothing else:

1. **`SKILL.md`: facts an agent cannot know.** Frontmatter `name: <project>-environment` and a one-line description of where this project's code runs and how its experiments are launched and collected. Then one line per fact: machines and SSH aliases, code, data, checkpoint, result and log paths, environment names and activation, resources and their limits, where the metric lands, verified quirks. Then a table of the scripts with their arguments and output. Do not explain general tools (conda, ssh, git, screen, pip, CUDA), restate defaults, or record guesses, results or research notes.
2. **`scripts/`: fixed procedures.** A procedure that runs the same way every time becomes a script, typically: sync code, prepare the environment, launch a named run, check a run, fetch its logs and results, stop it. Write only what this environment needs. Scripts use `#!/usr/bin/env bash` and `set -euo pipefail`, take arguments instead of being edited, read keys and tokens from `.contrejour/environment.json` (never inline them), and give every run its own name, log and result path so several experiments can run at once. A procedure that needs a browser uses [browser-act](../browser-act/SKILL.md) after `node .contrejour/dist/tools/ensure-browser-act.js`; create the browser and any login with the owner while writing the script and record the browser id as a fact, because a script cannot ask for approval. Never use Playwright, Selenium or Puppeteer.

Run every script once for real; for a launch, use a small, short run of the project's own entry point. Record only what ran. If a script cannot be made to work, report the environment step as incomplete with the real error; do not claim the environment is ready.

Later, when work reveals a new environment fact or a procedure repeated by hand, add it to this skill the same way: a fact line or a verified script.
